1. The reload bot

The bot drives Paytronix in a Chrome window you are logged into, so it runs on your PC rather than here. It gets its card list from this page and reports back to it.

small zip, already pointed at this app
  1. Unzip it first. Right-click the downloaded file → Extract All. Opening the zip and running from inside it will not work.
  2. Double-click 1 - SETUP - run me first.cmd. Python has to be on the machine; if it is not, this offers to install it, and tells you where to get it if your PC blocks that. Once per machine, ever.
  3. Double-click 2 - TEST RUN - adds no money.cmd to check it all works. It reads every balance and works out the amounts, but never fills in the Paytronix form and never ticks a card off. Safe to run any time, including before a reload is due.
  4. Each month, double-click 3 - RUN THE RELOAD - adds money.cmd and log into Paytronix when it asks. That one does add money.

Use the .cmd files, not the .ps1 ones beside them. Windows refuses to run a PowerShell script that arrived from the internet, so double-clicking the .ps1 appears to do nothing at all. The .cmd is the way in, and it changes no setting on the machine.

What the bot does to each card — follow this to do one by hand

Exactly the sequence the bot runs, written out so the reload can still happen if the bot breaks, or if someone has to cover it who has never used it. Work from the card list below — it has every card number and target.

  1. Log into Paytronix Account Lookup.
  2. Type the card number into the Card Number box and press Find Account. You land on the CSR Main Menu.
  3. Click Adjust Wallet.
  4. Choose the Stored Value wallet, then Next.
  5. Read Current Balance on the Input Amount page. What you add is target − current balance. If that comes out zero or less, the card is already at or above target — leave it alone and move to the next one.
  6. Fill the form in: Store = 1003 - Flowood MS, Operation = Add, Amount = the difference you just worked out, Comments = the cardholder's name. Then Next.
  7. Check the preview page, then click Adjust One Wallet.
  8. The Results page confirms it went through.
The amount is the difference, not the target. A card sitting at $112.40 against a $160.00 target gets $47.60 added — not $160.00. This is the one step that goes wrong by hand.

Cards you load by hand will not tick themselves off below. You do not need to do anything about that: the next time the bot runs it reads the balance, finds the card already at target, and marks it skipped.

2. The card list

Every meal card, what it should be topped up to, and which periods have already been loaded — one row per card, one tick column per period. This replaces the Gift Card spreadsheet: it is what the bot asks for when it runs, and what it ticks off as it goes. Anyone already ticked gets skipped, so re-running after a failure only picks up what is left.

If the card list changes
The cards below came with the app — there is nothing to set up. Re-import the spreadsheet only when the list itself changes: someone joins or leaves, a card is reissued, or a new year's tab starts. The file is Gift Card _ Meal Card Numbers - Support Center 2026.xlsx (not a .backup_ copy). It reads the tab named for the year picked below, shows what it found, and writes nothing until you confirm. If someone has been taken off the sheet because they left, it names them and offers to retire them.

3. Payroll report

Once the reload is done, upload the Paytronix Stored Value Sales and Added Value Detail Report. Export it as CSV — pick CSV on the Paytronix export screen rather than Excel. You get back that report with the names filled in, and the payroll adjustment sheet to hand over — the same two files as the old SSRS report. This is the monthly job; do it after every reload.
